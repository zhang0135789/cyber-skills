# Oral Copy Rewrite（口播文案二创加工）

## Overview

无固定领域基稿的动态二创流水线：用户投喂什么原文，就按同一套标准就地加工什么。体裁不设限（财经/心理/历史/国学/职场），加工力度由体检结果决定，默认最轻（原文好就不动笔）。

## 触发场景

- 用户发来一段口播文案/对标原文，说「审计」「校对」「看看」「优化」「复刻」「二创」「洗稿」
- 用户问「今天发什么」「推荐一篇文案」→ 从腾讯文档选题池取「待发布」或「待仿写」行加工
- 文案加工完成后用户说「入库」「存入腾讯文档」→ 归档流程

## 核心工作流（四步，顺序固定）

### 第一步：查重
- 与腾讯文档选题池（file_id=HUbUPTDlAMxT, sheet_id=BB08J2）现有行比对，与赛博大脑文案库比对。
- 重复稿直接标出，不发、不再加工。

### 第二步：体检（每篇必做，先于任何改笔）
按 references/rules.md 的标准逐项检查并出具体检报告：
1. 首句钩子检查（8点清单：独立成立、具体冲突、人类口语测试、标题测试、好奇债务测试）
2. 数字核实（全部数字逐个演算，错误的给出正确演算）
3. 字数检查（常规稿120-180字；>2000字触发拆集规则，见 references/conventions.md）
4. AI味扫描（禁词+逐行恒定价值检查）
5. 转写错误修正（无标点原始转写先断句，「X事→X是」类同音错标出）

### 第三步：分级加工（默认最轻，用户点名才升级）
| 档位 | 触发 | 动作 |
|---|---|---|
| A 校对级（默认） | 体检过关 | 只修错别字/标点/转写错误，原样发布，不动笔 |
| B 优化级 | 有弱句但结构好 | 只改标红弱句，结构故事全保留；首句不达标只重写首句 |
| C 复刻级 | 用户明确说「复刻/二创」 | 观点可借、表达必须重写、故事全换、数字核实后重演算、首句改冲突钩；不声明原创 |

### 第四步：交付与归档
1. **交付固定格式**：完整口播正文（永不只给片段或建议列表；A档只报修正处）→ 体检报告 → 发布元信息（首句兼标题、描述≤50字、10个标签）→ 改动清单（改了什么、为什么）。
2. **未经用户确认不归档**。用户确认后才写入腾讯文档对应行（L列正文 + 状态列）。
3. 归档后回读核验，并报告写入位置。

## 腾讯文档写入要点（踩过的坑）

- 写入工具：`set_range_value`（`set_cell_data`/`set_cell_range` 不存在）；读取用 `get_cell_data` + `return_csv:true`。
- **行号=序号-1**：序号146 → `row:145`。写前先读目标行确认序号，写后必须回读核验。
- 描述栏（≤50字）可能存有口播全文，补缺时不覆盖已有内容。
- values 格式：`[{"row":N,"col":C,"value_type":"STRING","string_value":"..."}]`。
